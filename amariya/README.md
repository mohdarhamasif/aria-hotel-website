# Amariya niche sites

Three landing pages for Amariya, one per niche, on one shared engine. Each has its own palette, display typeface, concept and live 3D orb.

| Route | Niche | Concept | Palette | Orb |
|---|---|---|---|---|
| `/hotels` | Hotels & restaurants | The Night Log | Forest & Champagne (dark) | Champagne lantern |
| `/clinics` | Physicians & clinics, including aesthetics | The Line | Ink & Porcelain (light) | Frosted porcelain |
| `/dental` | Dental practices | First Available | Rosé & Pearl (light) | Nacre pearl |

`/` is a small front door with the three doors; `/aesthetics` redirects to `/clinics`. Built with Astro 7, Three.js and Lenis (GSAP stays installed for the first tween that needs it; the frame loop is the browser's own requestAnimationFrame). The build spec is in `spec/build-spec.json`.

## Run it

```sh
npm install
npm run dev            # http://localhost:4321
npm run build          # static output in dist/
npm run preview        # serve dist/
npm run palettes       # regenerate colours and measure every pair
npm run typecheck      # tsc over the .ts modules (astro build does not type-check)
npm run check:funnel   # ROI, validation, qualification and clock checks
```

Browser checks run against `npx astro preview --port 4321 --host 127.0.0.1`, from `tests/browser` (puppeteer-core is installed there), one at a time: `node <script> http://127.0.0.1:4321 [niches...]`.

- `orbshots.mjs`, `motiontest.mjs`: the orb's states, reduced motion, Pause, a call's live region (software GL).
- `dragtest.mjs`: turning, throwing, keys and touch on the orb (the GPU; `GL=swiftshader` for software GL, where touch cannot keep real time).
- `functest.mjs`: structure and landmarks, voice and chat states, the start sheet, the agent's tools, ROI, every application form (messages, steps, focus, success, storage), keyboard paths, Pause and reduced motion.
- `navtest.mjs`: the agent's navigation, each page's chapter navigation by pointer and keyboard, the switcher, focus order and rings; the front door, `/aesthetics` and the 404 page at four widths.
- `nichetest.mjs`: the night, the house and the chips (hotels); the hand-off slip, the dial and the lens (clinics); the pearl's recesses, gaps and NOW line (dental).
- `contrasttest.mjs`: AA contrast of every visible line of text on its rendered background.
- `critshots.mjs <base> <outDir>`: review screenshots at 1920, 1440, 1024 and 390 px, with console errors and overflow in `index.json`.

## Where things live

- **Pages:** `src/pages/{hotels,clinics,dental}.astro` each render `src/niches/<niche>/<Niche>Page.astro`. A niche folder holds its page, CSS, components, `ui.ts` (page script), `presenter.ts` (the page's hands for the agent) and `scene/` (its 3D).
- **Copy, offer and prices:** `src/data/content/<niche>.ts` (typed by `types.ts`; unconfirmed claims are `pending(...)` and render nothing). Niche basics, agent IDs and URLs: `src/data/niches.ts`. The founders' prices are provisional; the issued/held counts will come from HubSpot.
- **Colours:** generated by `npm run palettes` (`scripts/palettes.mjs`) into `src/styles/tokens.css` and `src/data/colors.ts`. Edit the script, never the outputs; it fails if any measured pair drops below WCAG AA. Components use only `--color-*` roles.
- **Share images and icons:** `public/og/<niche>.png` (1200×630, each page's first screen at 16:00), `public/og/home.png` and the PNG icons (`apple-touch-icon.png`, `icon-192.png`, `icon-512.png`, drawn from `favicon.svg`) are captured from the built site; capture them again after a visible change to a first screen.
- **Fonts:** `astro.config.mjs`, self-hosted at build time; each page loads only its own faces. No italics anywhere (`global.css` bans them).
- **Shared CSS:** `src/styles/global.css`: reset, type scale, easing/duration/z-index tokens, buttons, the orb root, Lenis, the Pause rule, print.
- **Engine:** `src/scripts/`
  - `orb/stage.ts` renders the page's one orb on the fixed `.stage-canvas` (scissored to the orb's box, or the whole canvas for a full-frame scene), with state and tone blending, voice level, reduced motion, offscreen pausing, DPR caps and the slow-device fallback. `orb/input.ts` is direct manipulation (drag to turn with inertia, pitch spring, keys, touch) plus tap, long-press carry and drop events. `orb/boot.ts` loads the niche scene once the page is idle; without WebGL 2 the CSS still stays.
  - `motion/`: `scheduler.ts` (one frame loop on requestAnimationFrame), `scroll.ts` (Lenis on fine pointers, `sectionProgress`, `trackSections`, the polite navigator; `scroll.to(element)` stops short by the element's `scroll-margin-top` and the page's `scroll-padding-top` with or without Lenis, so each page sets where things land in its CSS), `prefs.ts` (reduced motion + Pause motion), `clock.ts` (the visitor's time).
  - `voice/bridge.ts` is the only voice module pages import; `session.ts`, `tools.ts` and `level.ts` connect ElevenLabs to it.
  - `apply/`: ROI, validation, qualification and the submission adapter. `text.ts`, `scripted.ts`, `sound.ts` and `analytics.ts` are small shared helpers.

## Connecting the voice agent and HubSpot

Environment variables (all optional, read at build time):

- `PUBLIC_ELEVENLABS_AGENT_ID_HOTELS`, `…_CLINICS`, `…_DENTAL`, falling back to `PUBLIC_ELEVENLABS_AGENT_ID`, then the shared agent.
- `PUBLIC_APPLY_WEBHOOK_URL`: applications are POSTed there as JSON. Without it they are kept in the visitor's browser (`localStorage.amariya_applications`) and logged.
- `PUBLIC_HUBSPOT_MEETINGS_HOTELS`, `…_CLINICS`, `…_DENTAL`: the meetings link shown to qualified applicants.

In the browser, `window.amariyaVoice` is the voice bridge (`simulate()` plays a preview call) and `window.amariyaOrb` the stage:

```js
amariyaOrb.setState('listening');        // 'idle' | 'connecting' | 'listening' | 'thinking' | 'speaking'
amariyaOrb.setTone('bright');            // 'warm' | 'bright' | 'soft' | 'calm'
amariyaOrb.setAmpSource((t) => level);   // 0–1
amariyaOrb.pose;                         // { yaw, pitch, speed, dragging }
```
